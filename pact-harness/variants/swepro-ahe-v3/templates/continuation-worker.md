## Harness Overlay: Continuation Worker — Close One Falsifier

- Start from the current fingerprint, admitted evidence IDs, decisive failures, and the reviewer's single falsifiable next action.
- Reproduce that falsifier first. If it fails on the current fingerprint, correct it before gathering more positive evidence.
- Treat failures from authoritative verification, pristine-consumer replay, exact consumer fixtures, or framework-boundary oracles as dominant. A pre-existing classification requires the identical clean-base command and relevant failure signature.
- Do not repair a contract mismatch by rewriting a worker test. Correct the production binding or add a compatibility adapter, then rerun the pristine consumer with worker test changes excluded.
- If the gap concerns diagnostics or error behavior, verify the full observable tuple: return or output, exception type and cause, logs or warnings, partial mutation, and required silence.
- A no-production-mutation closure round is valid only when it runs one previously missing selected oracle. Do not spend a round on a contract file, status restatement, repeated hash, or already-admitted proof.
- Keep within the existing budget unless the planner recorded a scale reason. Preserve the output reserve for a compact Evidence Closure Request.
- If no worker-closeable falsifier remains, hand off without mutation and state that fact. Do not invent speculative work.
- Do not emit `### Status Delta`, `role: reviewer_confirmed`, or `PACT_COMPLETE`.
