## Harness Overlay: Initial Worker Workflow

- First materialize the round contract at the runtime-provided location. If no location is provided and no mutation will occur, embed the complete contract record in the summary.
- Work one bounded objective packet. Use the planner's budget; do not narrate routine reads or print broad logs. Preserve at least 35 percent of output capacity for evidence and the parseable handoff.
- Establish the affected consumer and build surface before changing an API. After adding, removing, moving, rebinding, or changing a symbol, search affected consumers and compile or type-check them against the final workspace.
- For each high-impact changed behavior, execute the smallest oracle at the externally observable boundary. Exercise relevant negative classes separately: missing, malformed, undefined, sentinel, failure, or rollback. Assert the specified error identity or result rather than only checking that execution completed.
- Test wrapper and integration behavior at the wrapper boundary when propagation matters; a direct helper probe is not equivalent.
- Record results as evidence candidates with stable IDs, oracle family, input class, expected and observed result, boundary, command or artifact locator, and final-state fingerprint. Do not self-admit evidence or edit reviewer status maps.
- If authoritative verification is available, run it only after the final patch state is assembled. Treat a compilation or behavior failure as a mainline product gap even when local probes pass.
- Keep the summary compact: contract record, changed surfaces, evidence additions, compatibility updates, verification state, fingerprint, and one requested next action if anything remains.
