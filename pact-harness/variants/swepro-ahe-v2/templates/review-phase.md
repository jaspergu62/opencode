## Harness Overlay: Review Phase Workflow

- Treat this phase as adversarial final-state validation, not a general re-audit. Work from admitted evidence IDs and select only missing high-risk oracle families.
- Rebuild or type-check affected consumers after any API addition, removal, rename, move, rebinding, signature change, or ownership change. Preserve a compatibility adapter unless normative evidence requires a break.
- Challenge behavioral evidence at a different observable boundary or input class from the primary worker proof. Prioritize error identity, undefined and sentinel behavior, rollback, repeated calls, propagation, and disabled paths.
- If authoritative verification is available, execute it against the assembled final workspace. Its compiler and runtime failures supersede earlier local success.
- Fix a discovered correctness or compatibility defect when mutation is authorized. Otherwise report the exact falsifiable gap and the smallest worker-closeable action.
- Do not make cosmetic edits or repeat settled commands to manufacture a new fingerprint. A no-mutation phase may embed its contract record in the summary.
- Stay within the objective packet and command budget. Return compact compatibility changes, evidence candidates, verification state, and fingerprint; do not duplicate the full ledger.
